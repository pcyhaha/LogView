# LogView 运行与打包说明

本文档说明 LogView（基于 Electron + React + Monaco 的日志分析工具）的依赖安装、开发运行、构建与打包方式，以及常见问题的解决办法。

## 1. 环境要求

- **Node.js**：建议 18.x 或 20.x（与 Electron 30 兼容）。
- **npm**：随 Node 一同安装即可。
- **操作系统**：开发机为 Windows（本项目打包目标为 Windows NSIS x64 安装包）。

## 2. 安装依赖

在项目根目录执行：

```bash
npm install
```

该命令会：

1. 安装 `package.json` 中的运行时依赖（`react`、`monaco-editor`、`iconv-lite`、`chokidar`、`electron-store` 等）与开发依赖（`electron`、`electron-vite`、`electron-builder`、`vite`、`typescript` 等）。
2. 下载 **Electron 运行时二进制**（默认从 GitHub 拉取）。

### ⚠️ Electron 二进制下载失败的处理

在本机网络环境下，从 GitHub 下载 Electron 二进制可能失败（报 `Error: Electron uninstall` 或 `E_FAIL`）。此时需改用国内镜像：

```bash
# 设置国内镜像后重新触发 Electron 二进制下载
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
node node_modules/electron/install.js
```

下载成功后，`node_modules/electron/dist/electron.exe` 存在，`node_modules/electron/path.txt` 内容为 `electron.exe`，即可正常运行。

> 如果你所在网络可正常访问 GitHub，则 `npm install` 一步即可完成，无需上述镜像操作。

## 3. 开发运行

```bash
npm run dev
```

- 由 `electron-vite` 启动：先编译主进程（main）与预加载（preload），再启动渲染进程开发服务器（默认 `http://localhost:5173`），最后拉起 Electron 应用窗口。
- 渲染层（React）支持 **HMR 热更新**；修改主进程文件（如 `src/main/*`）时 `electron-vite` 会自动重建并重启主进程（菜单栏等会短暂重建）。
- 首次启动后，使用 `Ctrl+O` 打开日志文件，或点击工具栏按钮使用搜索、书签、时间线、跳转行、实时追踪（tail）等功能。

常用快捷键：

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl+O` | 打开日志文件 |
| `Ctrl+F` | 搜索 |
| `Ctrl+G` | 跳转行 |
| `Ctrl+F2` | 在当前行添加/移除书签 |
| `PageUp` / `PageDown` | 上一页 / 下一页 |
| `Esc` | 关闭当前侧栏或对话框 |

## 4. 构建（仅编译，不打包）

```bash
npm run build
```

由 `electron-vite build` 执行，将主进程、预加载、渲染进程分别编译输出到 `out/` 目录。用于验证代码可编译、产物结构正确。

## 5. 打包为 Windows 绿色版（单文件免安装）

### 方式一：双击 `package.bat`（推荐，最简单）

项目根目录已提供 `package.bat`，双击即可一键打包。它会自动：

1. 设置国内镜像 `ELECTRON_BUILDER_BINARIES_MIRROR=https://cdn.npmmirror.com/binaries/electron-builder-binaries/`，避免从 GitHub 下载 winCodeSign / nsis / nsis-resources 二进制失败；
2. 降低压缩级别 `ELECTRON_BUILDER_COMPRESSION_LEVEL=1`（大应用用最高 7z 压缩极慢且易触发 7za 报错）；
3. 执行 `npm run package` → `electron-vite build && electron-builder --win`，产出 `dist/LogView-1.0.0-portable.exe`；
4. 打包日志写入 `log/package.log`（统一归入 `log/` 目录，不污染根目录）。

> 约定：所有构建 / 打包 / 运行日志都输出到项目根下的 `log/` 目录；测试相关文件放到 `test/` 目录，与正式源码 `src/` 分离。

### 方式二：命令行打包

```bash
npm run package
```

等价于 `electron-vite build && electron-builder --win`。**但默认会从 GitHub 下载打包所需的二进制（winCodeSign / nsis / nsis-resources），本机网络很可能失败。**

因此命令行打包时请先设置国内镜像（关键写法见下方「⚠️ 镜像变量赋值坑」），**整行一次性执行**：

```bat
set ELECTRON_BUILDER_BINARIES_MIRROR=https://cdn.npmmirror.com/binaries/electron-builder-binaries/&&set ELECTRON_BUILDER_COMPRESSION_LEVEL=1&&npm run package > log\package.log 2>&1
```

> 提示：`&&` 前后都不要有空格。若拆成多行 `set ...` 再 `npm run package`，请务必保证 `=` 后的值末尾没有任何空格。日志会写入 `log\package.log`，请先建好 `log` 目录（或直接用「方式一」的 `package.bat`，它会自动创建）。

### ⚠️ 镜像变量赋值坑（必读）

electron-builder 的二进制下载器（Go 实现）对镜像地址非常敏感：

- **`set VAR=value &&`（即 `&&` 前带空格）时，空格会被吸进变量值**，导致 `ELECTRON_BUILDER_BINARIES_MIRROR` 变成 `...mirror/ `（尾随空格），拼出的下载 URL 变成 `...mirror/%20nsis-resources...`，最终 404 下载失败。
- 正确写法：`set VAR=value&&`（无空格）或把镜像写进 `package.bat`（bat 行尾无空格，没问题）。

### ⚠️ `package.bat` 在被重定向调用时的编码坑

`package.bat` 内含 `chcp 65001` 与 UTF-8 中文注释 / `echo`。若用 `cmd /c call package.bat >log 2>&1` 这种**重定向方式**调用，中文会被错误解析，报「不是内部或外部命令」，且末尾 `pause` 会占用日志句柄。

- **需要后台 / 重定向执行打包时，请改用上面「方式二」的内联命令**，不要 `call package.bat`。
- 正常双击 `package.bat` 不受影响。

### 离线兜底方案（镜像仍拉不到二进制时）

若镜像仍下不动 winCodeSign / nsis / nsis-resources 三个 `.7z`，可手动下载后起本地 HTTP 镜像：

```bash
# 1. 用 curl 从镜像下载三个压缩包
curl -O https://cdn.npmmirror.com/binaries/electron-builder-binaries/winCodeSign-2.6.0/winCodeSign-2.6.0.7z
curl -O https://cdn.npmmirror.com/binaries/electron-builder-binaries/nsis-3.0.4.1/nsis-3.0.4.1.7z
curl -O https://cdn.npmmirror.com/binaries/electron-builder-binaries/nsis-resources-3.4.1/nsis-resources-3.4.1.7z

# 2. 按 mirror/<name>-<ver>/<name>-<ver>.7z 摆放，并起本地服务
#    （目录结构：mirror/winCodeSign-2.6.0/winCodeSign-2.6.0.7z ...）
python -m http.server 8765
```

然后把镜像指向本地：`set ELECTRON_BUILDER_BINARIES_MIRROR=http://127.0.0.1:8765/`（注意末尾 `/` 且无尾随空格）再执行 `npm run package`。localhost 不会被按 UA 过滤，Go 下载器可正常拉取。

> 本机 7za 解压大应用时可能报 "System ERROR"，已在 `electron-builder.yml` 的 `portable:` 段设 `useZip: true` 改用 zip 内部归档规避，无需额外处理。

### 打包配置要点（`electron-builder.yml`）

- `appId: com.logview.app`，`productName: LogView`。
- `files`：包含 `package.json` 与 `out/**`，并排除源码 `src/*`、配置文件（`tsconfig*.json`、`electron.vite.config.*` 等）与开发资源，确保打包体积合理且运行正常。
- `win.target`：`portable`，架构 `x64`。
- `portable`：产物为单个可执行文件 `LogView-1.0.0-portable.exe`，**免安装、双击即用**，无需管理员权限、不弹 UAC；`useZip: true` 规避 7za 报错。

### 数据目录（纯绿色版：数据在 exe 同目录）

本程序唯一的持久化数据（设置、最近打开的文件、着色规则等）由 `electron-store` 保存。

- **开发模式（`npm run dev`）**：数据写入默认的 `AppData\Roaming\LogView\logview-settings.json`，不污染项目目录。
- **绿色版正式运行**：数据文件 `logview-settings.json` 直接写在 **exe 所在目录**下，实现「数据在同目录」的纯绿色版效果。

> 📌 实现细节：portable 单文件版运行时会先把自身解压到系统临时目录，此时 `app.getPath('exe')` 指向临时目录而非真正的 exe 位置。因此代码优先读取 electron-builder 注入的环境变量 `PORTABLE_EXECUTABLE_DIR` 来定位 exe 真实同级目录（见 `src/main/settings-service.ts`）。

因此把这个 exe 拷到任意可写目录（本地文件夹、U 盘等）双击即可运行，数据与 exe 同目录，整体拷贝 / 删除即可迁移或清理，无需触碰 `AppData`。

> ⚠️ 注意：请把 exe 放在**可写目录**运行（不要放在 `C:\Program Files\` 等系统目录），否则设置无法保存。

### 打包产物

生成的绿色版位于项目根目录下的 `dist/`（`electron-builder` 默认输出目录），文件名类似：

```
LogView-1.0.0-portable.exe
```

> 首次打包时，electron-builder 会按需下载打包二进制（winCodeSign / nsis / nsis-resources）。本机访问 GitHub 易失败，请按本节「方式一 / 方式二」设置 `ELECTRON_BUILDER_BINARIES_MIRROR` 国内镜像后重试；若仍失败，参考「离线兜底方案」。


## 7. 常见问题

**Q：运行 `npm run dev` 报 `Error: Electron uninstall`？**
A：Electron 二进制未下载成功。按第 2 节设置 `ELECTRON_MIRROR` 镜像后重新执行 `node node_modules/electron/install.js`。

**Q：打包时报 Electron/electron-builder 下载失败？**
A：同样是网络问题，设置 `ELECTRON_MIRROR` 后重试 `npm run package`。

**Q：界面是英文的？**
A：本项目界面文案已中文化（产品名 `LogView` 保留原文）。Monaco 编辑器内置右键菜单由 Electron 按系统语言自动本地化。

**Q：打开大日志文件很慢？**
A：程序采用分页 + 字节偏移行索引，默认每页 2000 行；超大文件会先建立索引，状态栏显示「索引中…」，完成后可流畅翻阅。
